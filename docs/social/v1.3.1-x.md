## スレッド版

### 1/3

Codex Desktopで `gpt-5.6-luna` 自体は動くのに、native `spawn_agent` が「Available models: Sol, Terra」と拒否するケースを再現しました。

Luna Research Skills v1.3.1で、診断から復元までを公開しています。

https://github.com/dj-thank/luna-research-skills/releases/tag/v1.3.1

### 2/3

ポイントは、direct CLIのLuna成功とnative childのLuna成功を分けること。

task名やnicknameではなく、child runtime metadataの `thread_source / model / effort` を確認します。静的configだけで「Luna verified」とは呼びません。

### 3/3

回避策は公式 `models_cache.json` を直接編集せず、専用catalogのLunaだけを `v1 → v2` にする方式です。

これはOpenAI公式修正ではない暫定策。backup/semantic diff/rollbackを必須にし、公式修正後は外せるようにしています。

## English short post

Luna can work directly while native `spawn_agent` still exposes only Sol/Terra on some Multi-Agent V2 surfaces. Luna Research Skills v1.3.1 documents a reversible community workaround: separate catalog, backups, rollback, and child runtime-metadata verification. Not an official OpenAI fix.

https://github.com/dj-thank/luna-research-skills/releases/tag/v1.3.1
